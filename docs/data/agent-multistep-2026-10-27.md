# 2026-10-27 有界多步 Agent 验证

新增的 LLM 模式已实现“公开计划 → 选择工具 → 读取观察 → 修订计划或继续 → 结束”的
执行循环，接入 `POST /agent/analyze` 及应用实际实验登记。六个只读工具由模型动态选择，
不再限于历史评测的一次工具调用。默认模式仍为确定性调用；使用见
[运行说明](../dev/autonomous-agent.md)。这是有限步数、只读、实验分析领域的能力，
没有跨请求记忆、后台自主任务或通用开放域推理质量保证。

## 修复与真实模型结果

本轮使用本地配置的外部模型 `deepseek-flash`。请求使用公开合成实验夹具，不上传
私有配置文件。凭据和端点未进入证据，提供方用量不是账单核验。

| 轮次 | 任务正常结束 | 原结构化评分 | 模型调用 | 已知 token |
|---|---:|---:|---:|---:|
| 初始实现，两个互斥分片合计 | 1/8 | 0/8 | 41 | 42,977 |
| 协议反馈修复后 | 8/8 | 8/8 | 34 | 37,097 |
| 引用字段安全修复后的最终运行时 | 8/8 | 6/8 | 36 | 39,424 |

初始失败包含不合法模型响应和引用格式错误，未删除失败或自动重试。随后服务端提供
可直接复制的规范引用与明确工具错误反馈。独立复审又发现元数据中的括号可混入引用，
最终实现对 ID、split、segment 的字符和长度进行严格验证，并限制来源；恶意字段被拒绝。

最终一轮原评分的两个失败来自评分器缺陷：任务先给列表工具传错来源，收到错误后纠正，
成功发现 ID，再完成配置、指标、失败样例等读取。原评分器要求“第一次工具调用必须
成功发现”，而任务要求是“所有依赖 ID 的读取必须在成功发现之后”。新评分器
`discovery-before-reads-v2` 允许发现前只有列表尝试，仍拒绝任何提前猜 ID 的读取。

对同一批最终轨迹修复评分器后，**事后复算为 8/8，新增模型调用 0**。原始 **6/8、FAIL**
结果完整保留；复算不是新实测，也不是预注册 8/8。源码、输入与原结果哈希及逐项差异
记录在归档的 `retrospective-rescore.json`。正反例覆盖列表纠错、空列表、提前读取和比较。

另外执行一次独立协议诊断，1 次调用、573 token，不计入任务成绩。初始异常的原始
模型文本未保存，不能用这次成功诊断反推所有早期异常的根因。

- 隔离 Agent 容器的真实 TCP HTTP 请求：4/4 模型调用成功，4,857 token，HTTP 200、
  `status=completed`，轨迹与引用检查通过。临时容器按其确切 ID 停止并移除。

容器镜像为 `sha256:b8c42b9b10d167dbd4fc9cd5fa4cbbfd6cae4e40102ee4343347978b27903b08`。
这是保留模型和依赖的基础镜像上复制源码、补齐 `httpx` 的验证镜像，不是生产 Dockerfile
从零重建。测试只启动 Agent 与本地登记，不能据此宣称整站数据库和搜索就绪。
生产 Dockerfile 已加入现有 `agent` 可选依赖，新增 Compose 覆盖文件显式转发 LLM 配置。
验证镜像包含另行研究的 arena=1 候选；本 Agent 发布不改变生产 arena=2 默认值。

全部轮次、诊断和两次 API 验证合计 **120 次外部请求、129,842 个已知 token**，均保留
已知/未知用量区分。没有为获得新评分而重新调用模型。

## 安全与验证范围

最终答案由服务端从已验证引用或工具数据摘要生成，不返回模型任意自由文本草稿。
跨来源或协议不一致时保守拒绝比较。公开计划可变化，但不记录模型内部思维链。
HTTP 错误终止本次运行，不做付费自动重试；有限的动作或工具错误纠正仍受同一预算约束。
覆盖总超时、单工具超时、步数、响应大小、工具参数白名单、并发上限与用量账本。

本轮本地默认单元套件、Ruff、格式和 Mypy 通过；3 个跳过不计通过，PG 集成由发布 CI
单独执行。本地套件含尚未发布的内存验证测试，以 PR 的精确 head CI 为发布依据。
八个任务只有四类合成场景的两个变体；结构化检查不证明自然语言解释质量、通用任务
规划能力或大规模服务稳定性。历史 46/50 两阶段评测与本轮成绩不能混用。
