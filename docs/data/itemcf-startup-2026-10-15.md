# 2026-10-15 ItemCF 内存与默认应用启动验证

默认推荐工厂每次启动均从真实用户历史拟合 ItemCF。旧实现会先保留全部无向共现对，
再建立双向邻居字典，最后只取每物品前 50 个邻居。此前默认应用启动曾停留在这个过程，
详见 [历史性能报告](performance-2026-10-14.md)；该报告中的超时与强制退出记录不变。

本轮改为建立物品到去重历史的倒排表，逐物品用 `Counter` 统计当前行的共现数，
按原相似度公式和 `(-score, item_id)` 顺序取邻居，处理完即释放行内统计。
没有截断用户历史、采样训练、替换模型或新增依赖。`predict` 完全未改；
零和负邻居上限继续遵循原 Python 切片行为。

计数时间仍为 `O(Σ h²)`，并非换成线性算法。正常正数 k 的空间为
`O(Σ h + max d + I·k)`，省去完整共现图及双向中间邻接表；正 k 使用 `nsmallest`，
负 k 仍需完整排序。本轮单独比较这一个 `fit` 实现变更。

## 真实数据对照

基线：`4d1746217942670f522fe09b5ca837d6b5b94f08`，数据版本 `d3a904f41240`。
完整历史有 50,000 用户、33,195 个不同物品，去重历史长度中位数 11、最大 546，
对应旧算法 21,747,094 次无向配对。数据、正式 `labels.csv` 和模型产物均未改动。

Windows、Python 3.12.6；四个独立进程按 A–B–B–A 顺序运行，选择 Parquet 原顺序的
前 5,000 用户。worker 先读取完整历史，再取子集；拟合计时不含读盘、序列化或预测。
内存是 Windows `GetProcessMemoryInfo` 在拟合结束时读取的**进程生命周期峰值工作集**，
包含历史加载，不是拟合阶段独占内存，也不包含随后序列化及预测验证的峰值。

| 轮次 | fit 秒 | 峰值工作集字节 | 模型及 5,000 用户 Top-10 预测 |
|---|---:|---:|---|
| A1 旧 | 3.343 | 530,616,320 | 相同 |
| B1 新 | 2.188 | 202,702,848 | 相同 |
| B2 新 | 2.000 | 202,739,712 | 相同 |
| A2 旧 | 3.187 | 531,120,128 | 相同 |

两轮均值：fit 3.265 → 2.094 秒（降低 **35.9%**），峰值工作集降低 **61.8%**。
只有两轮/版本，不能证明统计显著性或长期性能。完整邻居字典及逐用户预测采用
`sort_keys=True` 的规范 JSON SHA-256 对照，四轮均相同；不是原始 JSON 字节等价，
新实现的外层字典插入顺序可能变化。

随后候选对完整 50,000 用户完成拟合：**14.515 秒**，拟合结束时的进程峰值工作集
**364,986,368 字节**，并生成全部用户的 Top-10 预测指纹。
本轮**没有重跑全量旧实现**，没有完整 50,000 用户的新旧预测对照，因此不报告全量
加速比例。小样本精确对照与独立集合交集测试是语义保持证据，不能冒充全量对照。

## 默认应用真实 HTTP 验证

调用实际 `build_default_app()`，在同一进程交给单 worker Uvicorn，未使用 search-only
工厂，也未替换依赖为假对象。实际服务 PID 29760（launcher PID 1860），导入路径为
`E:\searchPilot\src\searchpilot\__init__.py`。数据、搜索模型、CTR 产物均来自当前仓库。
禁用数据库配置、使用内存反馈；因此这是**无数据库配置的默认应用启动验收**。
没有加载 `.env`、访问外部 LLM 或下载模型，模型缓存已存在并设置离线标志。

- 工厂构建 18.438 秒；从启动 launcher 到首次 HTTP ready 为 **19.781 秒**。
- 启动与结束时 live=200、ready=200；`search/recommend/feedback/vector_index/ltr/ctr` 均 true。
- 业务请求 **8/8 成功**：BM25、vector、hybrid、LTR 各一条；已有历史用户走 ItemCF、
  未知用户走 popular；CTR 一条；真实登记的 `sp-bm25` 实验读取一条。
- 四搜索模式均返回 5 条；两种推荐均返回 5 个不同 ID，rank 连续；CTR 概率有限且在
  `[0,1]`，模型与校准器版本非空。没有仅凭 ready=200 推断这些路由有效。
- 首次向量请求 **13.453 秒**，仍超过历史 10 秒目标。其余单请求不是压测，不报告 p95/p99。
- 请求完成后通过 Uvicorn `should_exit` 优雅关闭，退出码 0，端口已释放，没有强制结束。

启动监督循环门限为 120 秒，退出等待 15 秒。业务请求设置 HTTPX 各阶段 60 秒 timeout，
**不是完整响应的总 deadline**；原始 summary 的 `business_deadline_seconds` 名称过宽，
应按此解释。基准脚本的 Windows 单请求计时精度较粗，出现 0 秒不表示无耗时。
本轮不声称数据库整站启动、10 秒冷向量 SLA、并发容量、多 worker 或长期稳定性通过。
