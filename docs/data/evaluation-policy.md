# 搜索评估口径决定（2026-10-13）

本轮接手继续冻结 LTR、CTR 模型与在线默认策略。正式评估入口保留
`data/queries/labels.csv`，不以补标后某一模型的成绩变化作为更换入口的理由。
这是兼容现有实验的决定，不代表原始标注覆盖充分。

| 口径 | 输入与用途 | 结论边界 |
|---|---|---|
| 原始基线 | `labels.csv`；现有评估脚本默认入口 | 保留历史可比性；候选覆盖偏向 BM25 |
| 补标并集 | `labels.csv` + `labels_tool.csv`；`evaluate_pool_labels.py` 显式使用 | 两份文件无重叠；未标注文档按 0 分；LTR 候选仍未充分覆盖 |
| 只评已标注 | 同一并集，将未标注文档移出返回列表 | 仅说明已标注文档的相对顺序，不是完整召回或线上效果证明 |
| train/val 争议裁定 | `labels_adjudicated_train_val.csv` | 11 对工具文本裁定的独立覆盖层，尚未用于训练或评测 |

裁定文件不能直接作为第三份文件传给现有的 `merge_label_maps`：该函数对
冲突取最大等级，会吞掉降低等级的裁定。将来评估裁定口径时，应先按
`(query_id, item_id)` 精确替换补标中的对应记录，再与原始基线合并；必须另存
完整输入、哈希和报告，不改两份原始补标，也不覆盖旧报告。

本轮只裁定 train/val 的大分歧，不重标 test、不训练、不选择新模型。
裁定来自 Codex 对标题和摘要的解释，已经看过双方分数，不能作为第三轮盲标
或人工金标准；原有一致率仍按裁定前两份文件计算。具体理由及可复现检查见
[裁定报告](adjudication-train-val.md)。

交接中“是否改读并集”的开放决定在本轮采取保守结论：保留原始正式入口，
将补标及裁定作为命名清晰的独立协议。这样无需覆盖旧数据或追认新的历史结果。
