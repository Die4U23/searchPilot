本机 `127.0.0.1:18081/15432`，数据与模型目录只读挂载，没有读取私有 `.env`。

## 修复首次导入中断后的残缺数据

原 items 导入按批独立提交，catalog 按表、按批独立提交；启动却以 items 或 queries
存在任意行作为整步完成标志。因此第二批失败后，重启会跳过剩余数据。

真实 PostgreSQL 临时 schema 的修改前回归为 2 failed、2 passed：items 第二批违反
NOT NULL 后仍留下 `N1`；catalog 第二批标注违反 grade CHECK 后仍留下 1 query、1 label。
这次修改前输出保存在代理执行记录中，未另存原始日志，不冒充证据 ZIP 内的文件。

修复将每个 items 导入、每个完整 catalog 导入分别放入单一连接事务，保留批量执行。
任何批次失败都会回滚该整步；仍保留非空库不覆盖规则，不擅自修复历史残缺数据库。
不修改迁移、标签、模型或 annotator。新增四个数据库集成测试分别检查失败回滚与成功提交，
使用独立连接观察已提交状态，测试 schema 随后清理。

## 容器与协议

基线提交 `daf160580b09023e5f98cb878a81abd153eb183c`，加本轮脚本修复。
构建、执行镜像 ID 和容器源码哈希记录在机器可读材料中；不是拿客户端 checkout 代替
服务器来源。容器内使用 non-root 用户、CPU Torch 和构建时下载的 BGE 模型，运行时
`HF_HUB_OFFLINE=1`。外部 LLM 调用数为 0；镜像构建需要网络下载依赖和模型。

Docker Desktop Linux 引擎可用 12 个逻辑 CPU、8,171,180,032 字节内存，宿主 Windows，
客户端与服务同机。测量期间同一引擎存在其他任务容器，未控制宿主背景负载；不能将结果
解释为独占资源下的吞吐上限，也没有与旧版本进行性能 A/B 对照。

全新库启动到 HTTP ready 为 46.904 秒（含 Compose 启动、迁移、导入、服务构建）。
初始计数：5 次迁移、65,238 items、100 queries、1,012 labels、7 model_versions、
50 agent_tasks、65,238 bids、6 experiments、0 feedback。items/queries/labels 与当前
挂载文件独立核对，原 annotator 与实验来源另存审计结果。

初始业务检查覆盖四种搜索、已有用户 ItemCF/未知用户 popular、CTR 有限概率和版本、
PostgreSQL 实验读取、反馈创建/重放/冲突/未知物品。预期的 409 和 404 属于负向用例通过，
不能归入持续负载的成功请求。没有仅凭容器 healthy 或 ready 200 推断整站功能正常。

持续段为 600 秒、并发 4、100 条 CSV 查询、四搜索模式混合、limit 10。每种模式先顺序
预热 4 次，预热独立计账；正式 worker 公平轮转模式与查询，闭环无重试。到期停止派发，
在途请求按 10 秒总截止时间排空。延迟包含完整响应读取与契约校验，吞吐包含账本写入
及排空；闭环会在服务变慢时降低发送速率，不等于固定到达率压测。

每约 10 秒保存 API/数据库 `docker stats` 和 live/ready 请求；资源是离散采样，
并非连续峰值、进程独占 RSS 或泄漏证明。Docker CPU 百分比可以超过 100%（多个 CPU）。
运行后继续观察 30 秒恢复期，停止/重启 API，验证导入跳过与反馈持久性。

400 个查询/模式组合全部覆盖，重复请求的排序和完整结果指纹均一致。每分钟派发窗口
的所有请求均成功；原始汇总保留窗口分布，不把不同模式的混合分位数作为单模式 SLA。

正式窗口 **60 次 live/ready 采样全部 200**。API 内存显示值从 2.393 GiB 到 2.484 GiB，
采样最大值 2.484 GiB（约增加 93 MiB）；数据库采样内存为 112.3–115.2 MiB。

这些值由 Docker 显示的四舍五入数据换算，不能当作精确字节峰值或无泄漏证明。

启动、恢复及重启共 **17/17 业务检查符合预期**（12 个 200、3 个 201、1 个 409、
1 个 404）。恢复后四种搜索的完整响应去掉 request_id 后与启动时一致。
API 停止退出码为 0，重启日志为 `applied_migrations=[]`、`seed_steps=none`。
重放反馈返回原 event_id；最终所有导入表计数不变，仅反馈由 0 变为 1。
容器没有 OOM 标记或意外重启。

## 边界

本轮限定单 worker、并发 4、十分钟搜索混合负载；并非一小时/全天稳定性、容量上限、
固定到达率或跨机 SLA。推荐、CTR 和反馈仅做功能检查，未持续发压；未注入网络中断、
数据库不可用、进程强杀或 OOM。事务测试覆盖数据库异常回滚，不声称验证所有断电场景。
首次启动观察与本轮持续结果不替代检索相关性评估，也不更新历史实验指标。
