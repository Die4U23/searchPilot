# 有界多步只读 Agent

`POST /agent/analyze` 可通过服务端配置启用 LLM 决策循环：模型输出公开计划和一个工具
动作，服务端验证并执行，模型读取观察后决定下一步、修订计划或结束。工具读取应用
实际注入的实验登记；线上路径不强制使用评测夹具。默认仍为确定性模式，不发送模型请求。

## 使用

Python 安装 `pip install -e ".[agent]"`，设置环境变量后启动 API：

```powershell
$env:SEARCHPILOT_AGENT_MODE='llm'
$env:SEARCHPILOT_AGENT_LLM_ENDPOINT='https://provider.example/v1/chat/completions'
$env:SEARCHPILOT_AGENT_LLM_MODEL='your-model'
# 在本地安全配置 SEARCHPILOT_AGENT_LLM_API_KEY，不写入命令历史或仓库。
.venv/Scripts/python.exe scripts/run_api.py
```

端点示例不是已验证服务。应用不自动加载 `.env`。Docker 可从本地 `.env` 读取配置：

```powershell
docker compose -f docker-compose.yml -f docker-compose.agent.yml up --build
```

第二份 Compose 文件显式启用 LLM 模式并转发配置；不要把展开后的 Compose 配置、
容器完整环境或私有 `.env` 发布为证据。请求仍使用 `{"question":"..."}`，服务端继续
执行已有调用方令牌校验。响应增加 `mode`、`status`、`stop_reason`、`steps`、`plan`、
`usage`。`status=completed` 仅说明执行循环正常结束；调用方必须检查状态和停止原因。

## 执行和证据边界

- 每次模型决策只能输出一个白名单工具动作或结束动作；下一步依据实际工具观察。
- 六个只读工具不含 SQL、Shell 或任意网络访问。计划与公开动作记录在响应中；
  不请求、不保存模型内部思维链。未知工具、额外参数和无依据引用不能成为有效结果。
- 最终答案由服务端根据已验证的引用或工具数据摘要生成。模型的自由文本草稿不作为
  已验证答案返回；不会据此宣称开放域解释、推导或计算出的提升值已经验证。
- 模型可以选择证据和结束时机；来源或协议混杂时保守返回不可比较。仅查看配置
  或实验列表不会生成性能优劣结论。完整读取结果仍在 `tool_trace` 中，属于不可信数据。
- 默认每次运行最多 8 次模型请求、每次最多预留 2,048 输出 token、总计最多 16,384
  输出 token；预留不因实际少用而返还。输入 token 不包含在此限额，不能视为金额上限。
- 默认总执行时间 90 秒，单次 HTTP 请求 30 秒，单次工具读取 5 秒，HTTP 响应上限
  2 MiB，单条工具观察上限 32 KiB。模型或 HTTP 错误终止本次执行，不自动重试；
  模型返回的动作格式错误、可恢复工具错误可在原步数预算内修正。
- 每个应用实例最多同时运行 2 个 Agent 请求，超限返回 429；同步只读工具在进程内
  最多 4 个后台读取。Python 无法强制终止已进入的同步读取，超时后它可能继续，
  但本次 Agent 不会继续工具链。没有跨请求对话记忆或后台自主任务。
- `usage` 区分已知与未知用量，提供方未返回用量时保留未知。它不是账单核验。

## 验证

`python -m scripts.evaluate_agent_multistep` 默认输出 `UNRUN`，零外部调用。
显式 `--execute --out <新目录>` 执行 8 个公开合成任务：发现未知实验 ID、观察缺失
指标后修改计划、跨来源比较拒绝，以及配置中的指令注入。每个场景有两个 ID/数值
不同的版本；请求不提供目标 ID，后续工具参数必须来自发现结果。

固定套题最多预留 64 个请求、131,072 输出 token。支持 `--task-id` 与总请求上限，
输出目录必须是新目录；不续跑、不覆盖、不自动重试。输出包括输入、请求账本、
逐任务结果、源码/提示词哈希和独立的执行状态、结构化验收结果。

离线模拟只能证明执行机制。真实模型结果另行归档，不能沿用旧的两阶段 46/50
成绩证明新能力，也不能将这 8 个合成任务当作真实实验诊断质量或通用自主能力证明。
