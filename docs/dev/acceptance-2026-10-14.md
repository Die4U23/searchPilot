## 本轮实现

- 向量索引仅将逐元素 Python 有限值扫描改为 NumPy 批量扫描并转回同序整数列表。
  模型、矩阵点积、分数、heap 排序、并列 item_id 规则、类别过滤和正式标注均未改变。
- HTTP 压测逐请求保存结果字段指纹和 ID 顺序指纹，方便跨版本核对；模型版本另行比较。
  指纹不涵盖整个 HTTP 响应 envelope，不等于完整响应字节相同。
- 外部模型评测支持固定套题子集、请求总预算、输出总预算、单请求输出上限。
  发送前预留额度，未知或较小 usage 均不返还；保留全 50 题分母与未尝试、部分尝试状态。

性能实际测量、失败记录、原始证据和限制见 [A–B–B–A 报告](../data/performance-2026-10-14.md)。

## 外部验证和仍未满足的条件

本轮未发外部模型请求。仅在本项目 `.env`、当前进程环境和 GitHub 仓库配置名称中核对
模型配置；没有端点、模型或密钥，也没有可调度的仓库 Secrets/Variables。模型评测仍为
**UNRUN**；入口与两请求 smoke 命令在 [外部模型报告](../data/agent-llm-report.md)。
输入 token 不在输出预算内；输出预算不是金额预算，自由文本语义仍为 UNSCORED。

默认完整应用的启动尝试在真实用户历史的 ItemCF 训练中阻塞，未得到 ready。为隔离
唯一搜索优化，后续服务通过 `create_app(search=build_search_service(...))` 加载真实
索引、模型及同一生产搜索路由；推荐、反馈、CTR 和数据库不参与。全局 ready 返回 503
是这些组件未注入的预期状态，只检查 search/vector_index/ltr 就绪，不能据此宣称整站健康。

本轮没有证明默认完整应用启动、10 秒冷向量 SLA、长时稳定性、多机容量或外部模型质量。
这几个边界与优化前后所有请求分母一起保留，不用局部成功掩盖它们。
