# Git 交付约定

2026-10-13，项目所有者授权后续由代理自主完成分支、提交、PR 与 CI 检查。
该授权覆盖旧交接文档和本地规则中“代理只改工作区、由所有者手工提交”的限制。

1. 先核对工作区、远端、当前 PR、提交身份和本轮范围，保留无关改动。
2. 在 `codex/` 功能分支按内容分组，仅暂存明确列出的文件；不直接推送 main。
3. 使用所有者现有 Git 身份及其 GitHub 账号关联邮箱。提交 author/committer
   不使用 Codex、Claude 或其他代理身份；提交正文不添加任何 `Co-authored-by` trailer。
4. 本地验证后提交、推送到 origin、创建 PR。读取该 PR 最新 head SHA 的 CI，
   有失败就修复并等待该版本重新完成，不能用旧版本的绿灯代替。
5. PR 与提交不添加 AI 共同作者、贡献者署名或贡献者徽章。数据集中的 annotator
   与实验来源仍如实保留，它们是实验溯源字段，不是 Git 提交贡献者声明。
6. 交付时给出 PR、提交与 CI 状态及未测边界。创建 PR/提交不自动等同于授权合并；
   只有明确要求合并时才合并，并检查当时的 CI 与分支状态。

不提交 `.env`、凭据、原始数据、模型或本地私有配置；不 force-push，不改写历史
来修改贡献者统计。检查本轮提交的 author、committer、完整正文和 GitHub 归属后再交付。
